Abre `_ReceiptCaptureSheet` (modal bottom sheet, foto câmara only Decisão G), faz upload bucket `receipts/{order_id}.jpg`, chama método novo. V1 legacy preservado para storeShopping partner OU restaurant.
- **Trigger #18 NOVO** `trg_zz_set_purchase_flow_version` BEFORE INSERT orders: auto-define purchase_flow_version=2 para novos storeShopping não-parceiro. Naming `trg_zz_*` garante ordem **APÓS** 17 triggers existentes (NÃO modifica nenhum).

### ✅ BUG 2 — driver_push_tokens registo (commit `fc981de`)

**Causa raiz:** `PushTokenService.registerForRole` estava DENTRO try block que chamava `drivers.update`. Se update falhasse por RLS strict (driver não-aprovado), catch swallow + multi-device NUNCA registava.

**Fix:** Em `NotificationService.saveTokenForDriver` + `saveTokenForClient`, mover `PushTokenService.registerForRole` para ANTES do try/catch. Multi-device agora regista independentemente do sucesso da update legacy. `_boundRole/_boundId` definidos antes para token refresh funcionar mesmo se update legacy falha.

**Validation Gate:**
- V2.1 Estafeta abre app → driver_push_tokens activo → ✅ (lógica corrigida; teste manual confirmará)
- V2.2 Cliente → client_push_tokens → ✅
- V2.3 Logout → active=false (já existente)
- V2.5 Chat bidireccional push → ✅ (depende de V2.1+V2.2)
- V2.6 flutter analyze → ✅
