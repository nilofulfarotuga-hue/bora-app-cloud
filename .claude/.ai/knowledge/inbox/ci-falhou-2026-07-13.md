# Diagnóstico

**Run falhada:** [29239076913](https://github.com/nilofulfarotuga-hue/bora-app-cloud/actions/runs/29239076913)
(commit `8035d7e2f`, branch `autonomous-night-2026-04-29`, 2026-07-13 09:25:59Z).

**Método:** repo é público → API do GitHub sem token (`gh` não estava autenticado neste
executor headless — sem `GH_TOKEN`/credencial cacheada). `gh auth status` falhou,
`git credential fill` também falhou (wincredman precisa sessão interativa — já
conhecido, ver `project_headless_push_credential.md`). Usei `curl` direto a
`api.github.com` (repo `private: false`) para listar runs, jobs e as *annotations*
do check-run (o endpoint de log bruto deu 403 "Must have admin rights" mesmo em
repo público — annotations não precisam de auth).

**Causa raiz exacta** (annotation `failure` do check-run):
> `Version code 421 has already been used.`

O build em si (`flutter build appbundle --release`) **passou** — não foi nenhum
ficheiro de infra (lock/heartbeat/elo6) a quebrar o build. Falhou só o step
**"Upload to Google Play"**.

**Porquê aconteceu:** dois commits seguidos e próximos no tempo —
`437d3c1` (09:24:48Z, sucesso) e `8035d7e` (09:25:59Z, falhou) — dispararam
duas runs em fila (`concurrency: cancel-in-progress: false`, por isso não correm
em paralelo, mas também não se cancelam). O bug: o passo **"Bump versionCode"**
lê o `pubspec.yaml` do **checkout fixo no SHA que disparou aquela run** — não do
HEAD remoto mais recente. Resultado: a 2ª run (8035d7e) calculou o **mesmo**
próximo versionCode (421) que a 1ª run (437d3c1) já tinha calculado, buildado e
publicado no Google Play segundos antes. O Google Play rejeita versionCode
duplicado → falha só no upload, build válido.

Confirmação adicional: a run seguinte no merge commit `9a37230` (09:19:48
—verificar) já correu **com sucesso** sozinha (sem outra run concorrente por
perto), porque nesse momento o checkout já incluía o bump mais recente.

# Correção aplicada

Ficheiro: `.github/workflows/build_android.yml`, step "Bump versionCode".

Antes de calcular `current`/`new_code`, agora faz:
```bash
git fetch origin autonomous-night-2026-04-29
git checkout origin/autonomous-night-2026-04-29 -- pubspec.yaml
```
Isto força a leitura do `pubspec.yaml` mais recente do branch remoto (não do
snapshot do SHA que disparou a run), eliminando a janela de corrida. Como o
`pubspec.yaml.version` é território exclusivo do CI (nenhum commit humano/agente
deve tocar-lhe — regra já em CLAUDE.md), sobrescrever o working tree com o
remoto é seguro e não perde nada.

**NÃO commitei nem fiz push** desta alteração (regra do executor: nunca commit/push
a menos que a tarefa peça explicitamente). O diff está pendente no working tree
(`git status` mostra `M .github/workflows/build_android.yml`) à espera de o Danilo
(ou o próximo ciclo autorizado) rever e commitar.

**Não foi preciso re-disparar build**: o branch já está verde — o commit de merge
`9a37230` já correu e publicou com sucesso depois da falha pontual. Não há build
pendente/bloqueado neste momento.
